# ADR-041 — P&L Attribution Model in Trade Blotter

**Date:** 2026-05-01
**Status:** Accepted (Revised)
**Repo:** theonlykk/candlelab
**Author:** Khalid Khan (Lead Engineer)
**Reviewer:** Gemini (Staff Architect)

---

## Context

Theo P&L (USD) and OANDA P&L (CAD) cannot be compared directly.
Two sources of divergence exist:
1. Execution slippage — entry/exit price differences between
   simulation and live broker
2. FX drift — static `PIP_VALUES` approximation vs actual CAD/USD
   settlement rate

Previous ADR-041 revision used static pip-based USD conversion —
circular logic that used Theo math to verify Theo.

## Decision

P&L Attribution Model — three baselines, two variance vectors.

**Baselines:**
- `Theo P&L (USD)`: `theo_pips × static_pv × units / 100_000`
- `OANDA Eq (USD)`: `oanda_pips × static_pv × units / 100_000`
  — same math as Theo, isolates execution slippage from FX noise
- `OANDA Real (USD)`: `oanda_pl_cad × live_cad_usd_rate`
  — absolute settled ground truth converted at display time

**Deltas:**
- `Exec Delta`: `OANDA Eq - Theo P&L`
  — pure execution slippage, no FX noise
- `FX Delta`: `OANDA Real - OANDA Eq`
  — approximation error from static PIP_VALUES vs live rate

**Live rate:** `_fetch_cad_usd_rate()` calls OANDA pricing API
(`GET /v3/accounts/{account}/pricing?instruments=USD_CAD`) at page
load time. Returns `None` on failure — dependent columns show `—`.

## Columns in Trade Blotter

| Column | Source | Currency |
|--------|--------|----------|
| Theo Agg P&L (USD) | Simulation | USD |
| OANDA Eq (USD) | Pip math, same as Theo | USD |
| Exec Delta | OANDA Eq − Theo | USD |
| OANDA Real (USD) | CAD × live rate | USD |
| FX Delta | OANDA Real − OANDA Eq | USD |
| OANDA Real (CAD) | Book of record | CAD |

## Consequences

- Exec Delta isolates execution quality — slippage, timing
- FX Delta isolates currency approximation error
- Both deltas should be near zero for a well-calibrated strategy
- `oanda_pl` (CAD) preserved as immutable book of record
- `_fetch_true_pnl()` unchanged — My Strategies card stays in CAD
- FX rate fetched once per page load — ~100ms overhead acceptable

## Negative Space

- Does NOT store CAD/USD rate in trades table
- Does NOT change executor
- Does NOT convert `_fetch_true_pnl()` to USD
- Does NOT add FX hedging or multi-currency accounting
