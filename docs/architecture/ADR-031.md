# ADR-031 — api_strategy_executor_pnl Granularity Fix

**Date:** 2026-04-29
**Status:** Accepted
**Repo:** theonlykk/candlelab
**Author:** Khalid Khan (Lead Engineer)
**Reviewer:** Gemini (Staff Architect)

---

## Context

ADR-030 Phase 3 threaded `granularity` through all simulation layers
but intentionally left `api_strategy_executor_pnl` unpatched because
`interval` was not available in scope at that call site. For M15/H1
strategies, `run_since_live()` was returning M5 candle data, producing
incorrect Theo P&L figures.

## Decision

Option A — Call `_hydrate_strategy_config(strategy_name)` at the top
of the route handler to retrieve `interval`, resolve `granularity` via
`INTERVAL_MAP`, and pass it to both `run_since_live()` calls.

**Rejected:**
- Option B (interval in POST body): violates Backend State Supremacy.
  Client must never dictate the physical properties of a strategy.
- Option C (extend `_fetch_metrics_anchor_ts`): unnecessary blast
  radius. Warps a narrowly scoped helper to save a sub-millisecond
  DB query.

## Changes

- `app.py`: `api_strategy_executor_pnl` now calls
  `_hydrate_strategy_config(strategy_name)`, returns 404 if strategy
  not found, resolves `granularity` from `interval` via `INTERVAL_MAP`,
  passes `granularity=granularity` to both `run_since_live()` calls.

## Consequences

- M15/H1 strategies return correct Theo P&L from executor-pnl route.
- Route returns 404 for unknown strategies — consistent with
  `api_strategy_pnl` behaviour.
- One additional primary key lookup per request on
  `candlelab_strategies_live` — sub-millisecond overhead, acceptable.

## Negative Space

- Does NOT change `run_since_live()`.
- Does NOT change `_hydrate_strategy_config()`.
- Does NOT change any other route.
- Does NOT touch `simulation_engine.py`, `strategy_runner.py`,
  or `data.py`.
